# Поведенческая спецификация UI

> Документ описывает **структуру и поведение** интерфейса: что где находится,
> что происходит при каждом действии. Визуальный стиль (цвета, иконки, шрифты,
> радиусы, тени) описан отдельно в `docs/design-system.md`.
>
> Пометки:
>
> - **[решение]**: поведение не подтверждено, выбрано нами, можно менять;
> - **[уточнить]**: ждёт ответа, до ответа реализовать как [решение].
>
> Решения, принятые перед этапом 0, записаны в `docs/decisions.md`. Поведение, которое они
> добавили или изменили, помечено в этом документе как [решение].

## 0. Платформы

- Windows (основная для ручного тестирования), macOS, Linux. Позже iOS и Android.
- Горячие клавиши указаны для Windows/Linux. На macOS Ctrl заменяется на Cmd
  там, где это принято на платформе; набор клавиш Mac описан в 12.5. [решение]
- Элементы функций поздних этапов (см. SPEC.md, «Порядок работы») скрываются флагом
  этапа, а не показываются неактивными. [решение]
- Интерфейс на английском. Строки интерфейса в этом документе задают смысл, финальные
  тексты лежат в i18n-каталоге (`en`). e2e-тесты ищут элементы по `data-testid`, а не по
  тексту. [решение]

## 1. Главное окно

### 1.1 Верхняя панель (заголовок окна)

- Собственный заголовок окна (frameless). На Windows/Linux кнопки
  свернуть / развернуть / закрыть справа, на macOS системные кнопки слева. [решение для macOS]
- Слева направо:
  1. Кнопка меню приложения.
  2. Постоянная вкладка **Vaults**: рабочая область управления данными.
     Рядом стрелка-переключатель текущего vault (личный, командные).
  3. Постоянная вкладка **SFTP**: SFTP-менеджер для ручной работы (раздел 5). [решение]
  4. Вкладки открытых сессий: иконка ОС хоста + имя хоста.
     - У активной вкладки (и у любой при наведении) на месте иконки ОС
       появляется кнопка закрытия.
     - Активная вкладка отмечена полосой `--accent`. Цвета темы терминала хоста
       для неё не используются. [решение]
     - Справа на вкладке значок типа сессии: терминал или SFTP. Вкладку-сессию SFTP
       открывает «Connect через SFTP» (см. 5.1). [решение]
  5. Кнопка «+»: новая вкладка со стартовой страницей (см. раздел 6).
- Справа:
  - кнопка обновления (видна, только когда проверка нашла обновление, см. 12.7);
  - центр уведомлений (см. 1.5);
  - кнопка показа и скрытия боковой панели терминала (только когда активна
    вкладка сессии, см. 4.2);
  - кнопки окна.

### 1.2 Боковая панель (внутри вкладки Vaults)

- Разделы сверху вниз: **Hosts**, **Keychain**, **Port Forwarding**, **Snippets**,
  **Known Hosts**, **Logs**.
- Активный раздел подсвечен. Каждый раздел открывает свой экран в основной области.

### 1.3 Правая панель деталей

- Выдвижная панель справа. Открывается при выборе объекта или при создании нового.
- В шапке: заголовок («детали хоста» / «новый хост»), меню «…» с дополнительными
  действиями (состав зависит от объекта, для хоста см. 3.3), кнопка свернуть панель.
- Основная область сужается, панель её не перекрывает. [решение]
- Правило сохранения для всех панелей объектов (хосты, группы, ключи, identities, правила
  форвардинга, сниппеты) [решение]:
  - новый объект создаётся, когда все его обязательные поля заполнены корректно.
    До этого он черновик, и при закрытии панели черновик отбрасывается без вопросов;
  - после этого изменения сохраняются автоматически, кнопки сохранения нет;
  - некорректное значение подсвечивается, под полем указана причина, и оно не
    сохраняется. Действует последнее корректное значение;
  - единственное исключение — мастера с явной кнопкой «Создать» (8.3).

### 1.4 Меню приложения (кнопка с тремя полосками)

1. Vaults (Ctrl+1).
2. SFTP (Ctrl+2).
3. Settings (Ctrl+,).
4. — разделитель —
5. New Local Terminal.
6. New Serial Connection.
7. Edit ▸: отменить, повторить, вырезать, копировать, вставить, выделить всё. [решение]
8. View ▸: масштаб интерфейса, полноэкранный режим, показать или скрыть
   боковую панель. [решение]
9. Window ▸: новое окно, следующая и предыдущая вкладка, закрыть вкладку. [решение]
10. Help ▸: документация, сообщить о проблеме (ссылка на issues), проверить
    обновления, о программе. [решение] «Проверить обновления» доступна всегда, даже
    когда автопроверка выключена (см. 12.7). [решение]
11. Lock: заблокировать приложение сейчас (см. 13.3). [решение]
12. — разделитель —
13. Exit. Пока есть активные сессии, форварды или передачи файлов, Exit запрашивает
    подтверждение (см. 4.6). [решение]

Дополнительно:

- Клавиши в подсказках пишутся символами (`Ctrl+,`), а не словами на языке
  системы. [решение]
- На macOS вместо этого меню используется системная строка меню с теми же
  пунктами. [решение]
- Все окна равноправны: у каждого окна свои вкладки, а изменения данных и настроек
  сразу видны во всех окнах. Переноса вкладок между окнами в MVP нет. [решение]

### 1.5 Центр уведомлений [решение]

- Кнопка центра уведомлений в верхней панели (1.1) открывает список уведомлений, новые
  сверху. Счётчик на кнопке показывает число непрочитанных.
- Новое уведомление появляется тостом на 5 секунд и остаётся в списке. Открытие списка
  отмечает все уведомления прочитанными.
- Пример источника: загрузки файлов, открытых из SFTP (5.4).
- Уведомления хранятся только в памяти и пропадают при выходе из приложения. Системные
  уведомления ОС не используются.

## 2. Экран Hosts

### 2.1 Поиск и быстрое подключение

- Строка поиска вверху основной области, на всю ширину. Плейсхолдер подсказывает,
  что можно искать хост или ввести `ssh user@hostname`.
- Ввод фильтрует группы и хосты в реальном времени: по имени, адресу,
  тегам и имени пользователя. [решение по набору полей]
- Если строка распознаётся как адрес подключения (`host`, `user@host`,
  `user@host:port`, `ssh user@host -p port`), в правой части строки активируется
  кнопка Connect. Enter или клик подключает без сохранения хоста.
- Одиночное слово (форма `host`) считается адресом, только если в нём есть точка или
  двоеточие, это IP-адрес или `localhost`. Любое другое одиночное слово — только
  поисковый запрос. [решение]
- Если текст точно совпадает с label или адресом сохранённого хоста, Enter и кнопка
  Connect подключают этот сохранённый хост с его настройками. [решение]
- Если в строке нет имени пользователя и хост его не задаёт, имя пользователя
  запрашивается при подключении (см. 4.8). [решение]
- Пока строка не является адресом, кнопка Connect неактивна.
- После успешного быстрого подключения ненавязчиво предлагается сохранить хост. [решение]

### 2.2 Панель действий

Слева:

- Split-кнопка **New host**. Основная часть создаёт хост, стрелка открывает меню:
  1. **New Group**: создать группу в текущем расположении. Открывается панель группы
     (см. 3.4). [решение]
  2. **Import**: диалог импорта (см. 2.5); форматы перечислены в SPEC.md, раздел
     «Импорт».
  3. Интеграции с облаками (AWS, DigitalOcean, Azure): подключение аккаунта
     провайдера и импорт его серверов как хостов. **Отдельный поздний этап**,
     в MVP пункты скрыты.
- **Terminal**: открыть локальный терминал в новой вкладке. Оболочка по умолчанию
  задаётся в настройках (на Windows PowerShell / cmd / WSL). [решение]
- **Serial**: подключение по последовательному порту, открывается отдельной
  вкладкой в верхней панели.

Справа:

- Переключатель вида: плитки / список.
- Фильтр по тегам.
- Меню сортировки: вручную, по имени, по дате создания, по дате изменения. «Вручную» —
  режим по умолчанию на Hosts, и только в нём перетаскивание меняет порядок карточек
  (см. 2.3). Иконка та же, что на других экранах (см. 7.1). [решение]
- Аватары участников текущего vault и кнопка «+». Клик открывает выпадающее меню:
  пункт «Пригласить участников», ниже список текущих участников (аватар + email).
  «Пригласить участников» открывает диалог приглашения (см. 12.3). [решение]

### 2.3 Содержимое экрана

- Два раздела: сверху **Groups**, под ним **Hosts**.
- Группы работают как папки: клик открывает группу, внутри видны её подгруппы
  и хосты. Над содержимым путь (хлебные крошки) с возвратом на любой уровень. [решение]
- Карточка группы: иконка, название, количество хостов (включая вложенные группы). [решение]
  Правый клик открывает меню группы (см. 3.4). [решение]
- Карточка хоста:
  - иконка ОС. Дистрибутив определяется при первом успешном подключении
    (см. 12.4, блок «Определение ОС»). До этого показывается нейтральная иконка.
    Иконки ОС берутся из набора с подходящей лицензией, с учётом
    trademark-политик дистрибутивов;
  - заголовок: label, а если он пустой, то адрес;
  - подзаголовок вторичным цветом, через запятую: протокол(ы), имя пользователя,
    затем группа или теги;
  - длинный текст обрезается многоточием.
- Сетка адаптивная: число колонок зависит от ширины основной области.
- Выбранная карточка визуально выделена.
- На карточке объекта с неразрешённым конфликтом синхронизации показан бейдж конфликта
  (см. 13.6). [решение]
- Поддерживается множественное выделение: Ctrl+клик добавляет или убирает
  карточку, Shift+клик выделяет диапазон. Действия контекстного меню, которые
  применимы к нескольким хостам (Connect, Add to Workspace, Move to, Copy to,
  Remove), выполняются для всех выделенных. [решение по клавишам и составу]
- Карточки можно перетаскивать [решение по деталям]:
  - в режиме сортировки «вручную» (см. 2.2) перетаскивание внутри списка меняет порядок.
    В других режимах сортировки порядок не меняется; [решение]
  - при броске на карточку группы хост переносится в эту группу в любом режиме
    сортировки.
- Промо-баннеры не нужны. Вместо них пустое состояние с подсказками. [решение]
- Пустое состояние (нет хостов): короткое пояснение и кнопки «Создать хост»
  и «Импортировать из ~/.ssh/config». Вторая открывает диалог импорта (2.5) с выбранным
  источником `~/.ssh/config`. [решение]

### 2.4 Действия с карточкой хоста

- Одинарный клик: выделить карточку и показать детали в правой панели.
- Двойной клик: подключиться (новая вкладка сессии).
- Enter на выделенной карточке: быстрое подключение.
- E на выделенной карточке: редактирование (детали с фокусом в первом поле).
- Стрелки клавиатуры перемещают выделение по сетке. [решение]
- Правый клик открывает контекстное меню (порядок важен):
  1. **Quick Connect** (Enter): подключиться по основному протоколу.
  2. **Connect ▸**: подменю:
     - через SSH (сессия терминала);
     - через SFTP: открывает новую вкладку-сессию SFTP с хостом в правой панели
       (см. 5.1); [решение]
     - разделитель;
     - подсказка «в новом окне»: если при выборе любого варианта держать Alt,
       сессия открывается в новом окне приложения. Alt + двойной клик по
       карточке работает так же. [решение для двойного клика]
  3. **Add to Workspace ▸**: добавить в сохранённое рабочее пространство
     (подробно в разделе «Терминал»).
  4. **Edit Host Details** (E).
  5. **Collaborate**: открывает диалог «Перенести или скопировать в vault» (см. 2.6)
     с командным vault в качестве цели. Единица шаринга — vault целиком, а не отдельный
     хост. [решение]
  6. **Move to ▸**: перенести в другой vault или группу. Перенос в другой vault идёт
     через диалог из 2.6. [решение]
  7. **Copy to ▸**: скопировать в другой vault через диалог из 2.6. [решение]
  8. **Duplicate**: копия хоста, к имени добавляется суффикс « Copy».
  9. **Copy Link**: ссылка на хост в собственной URL-схеме приложения
     (`shellpp://host/<id>`). Значок (i) поясняет, кто сможет открыть ссылку.
  10. **Remove**: удаление с подтверждением и возможностью отменить
      действие (undo) несколько секунд. [решение]

### 2.5 Диалог импорта [решение]

- Открывается из New host ▸ Import (2.2), из пустого состояния Hosts (2.3) и кнопкой
  Import на экране Known Hosts (10.1). Модальный диалог по шагам:
  1. **Источник**: `~/.ssh/config`, сессии PuTTY (только на Windows), CSV, собственный
     JSON, known_hosts.
  2. **Файл**: поле пути, заполненное путём по умолчанию для источника (например,
     `~/.ssh/config` или `~/.ssh/known_hosts`), и кнопка выбора другого файла.
     Сессии PuTTY читаются из реестра Windows, поэтому для них шаг пропускается.
  3. **Предпросмотр**: найденные записи, у каждой статус «новый», «уже есть» или
     «ошибка» (с причиной). Импортируются только «новые» записи.
  4. **Итог**: «добавлено N, пропущено M, ошибок K».
- Колонки CSV: `label`, `address`, `port`, `username`, `group`, `tags`.
- Импорт идемпотентен. Запись сопоставляется по ключу источника: тип источника плюс
  Host alias, имя сессии PuTTY или UUID записи. Запись без ключа источника сопоставляется
  по (address, port, username). Существующие записи никогда не перезаписываются, даже если
  их изменили после прошлого импорта.
- `~/.ssh/config`: ключи из `IdentityFile` импортируются в Keychain. Для зашифрованного
  ключа запрашивается passphrase (как в 7.3).
- known_hosts: хэшированные записи и маркеры обрабатываются, как описано в 10.1.

### 2.6 Перенос или копирование в vault [решение]

- Открывается из Collaborate, Move to ▸ и Copy to ▸, когда цель — другой vault (2.4, 8.2),
  из Share this host (3.1) и Share this snippet (9.3).
- Поля: целевой vault и операция (перенести или скопировать).
- Объект перешифровывается ключом целевого vault и становится новой записью с новым id.
  Ссылки на старую запись, созданные через Copy Link (2.4), перестают работать.
- Связанные объекты (identity, ключ, startup snippet, jump hosts) перечислены, выбор один
  для всех:
  - **Отвязать** (по умолчанию): связанные объекты остаются на месте, а перенесённый или
    скопированный объект больше на них не ссылается;
  - **Скопировать вместе**: связанные объекты копируются в целевой vault.
    Предупреждение говорит, что все участники целевого vault, включая viewer, смогут
    прочитать их секреты.
- Хост в командном vault может быть без credentials. Каждый участник привязывает к нему
  свой SSH ID или identity в панели хоста. Эта привязка хранится в личном vault участника
  и не видна другим участникам (см. 12.3).

## 3. Панель хоста: просмотр, создание, редактирование

Одна и та же форма для создания и редактирования, открывается в правой панели.

### 3.1 Блоки сверху вниз

1. **Vault**: выпадающий список, где хранится хост (личный или командный vault).
2. **Address**: иконка ОС + поле «IP или hostname». При создании фокус сразу здесь.
3. **General**:
   - Label;
   - Parent Group: выбор группы с поиском и созданием новой на лету; [решение]
   - Tags: теги показаны чипами с кнопкой удаления, ввод с автодополнением
     и созданием новых тегов на лету;
   - Color: один из 8 цветов плитки (`docs/design-system.md`, 3.1), по умолчанию
     graphite; [решение]
   - Notes: многострочное поле для произвольного текста; [решение]
   - Backspace: что отправляет клавиша Backspace (по умолчанию / варианты). [решение: Default, `^?` (DEL), `^H`]
4. **Share this host**: открывает диалог «Перенести или скопировать в vault» (см. 2.6).
   Неактивна, пока хост не создан. [решение]
5. **SSH**:
   - порт: поле в одной строке с названием протокола, плейсхолдер 22;
   - Credentials:
     - подсказка над полями, если такой же логин с паролем или ключом используется
       ещё в N хостах: предложение одной ссылкой объединить их в identity.
       После создания identity все эти хосты ссылаются на неё, и смена пароля
       в одном месте применяется ко всем;
     - username;
     - password: маскирован, есть кнопка показать/скрыть;
     - привязанный ключ показан отдельным полем с именем ключа из Keychain,
       его можно отвязать;
     - кнопка «+» для привязки identity, ключа, сертификата или FIDO2-ключа.
       Уже привязанный тип из списка вариантов пропадает.
       Для ключа список предлагает существующие ключи и короткий путь добавить новый:
       вставить текст ключа или выбрать файл. Для зашифрованного ключа запрашивается
       passphrase (как в 7.3), и ключ сохраняется в Keychain; [решение]
     - значения, унаследованные от родительской группы (username, identity или ключ,
       port, Host Chaining), показаны плейсхолдером «из группы X». Значение, введённое
       в хосте, перекрывает унаследованное (см. 3.4); [решение]
     - в командном vault хост может быть без credentials: каждый участник привязывает
       свой SSH ID или identity (см. 2.6). [решение]
   - «Show more» раскрывает дополнительные настройки, по одному полю на строку:
     - Agent Forwarding: вкл/выкл, по умолчанию выключен;
     - Startup snippet: сниппет, который выполняется сразу после входа;
     - Host Chaining: цепочка промежуточных хостов (jump hosts);
     - Proxy: HTTP или SOCKS-прокси для подключения;
     - Environment Variables: переменные окружения для сессии;
     - Charset: кодировка, по умолчанию UTF-8;
     - Keepalive: интервал в секундах; пусто — глобальное значение (см. 12.4); [решение]
     - Record history: как в настройках / вкл / выкл, по умолчанию «как в настройках»
       (см. 4.2, 12.4); [решение]
     - Record output: как в настройках / вкл / выкл, по умолчанию «как в настройках»
       (см. 11.2, 12.6); [решение]
     - Mosh: вкл/выкл, по умолчанию выключен;
     - тема терминала для этого хоста: миниатюра-превью + название, клик
       открывает выбор темы. Набор тем собственный, по умолчанию тёмная тема.
6. **Add Telnet**: добавить к тому же хосту второй протокол со своими настройками.
7. Кнопка **Connect** закреплена внизу панели. Неактивна, пока не заполнен адрес.

### 3.2 Поведение

- Действует правило сохранения из 1.3. Единственное обязательное поле хоста — адрес. [решение]
- Изменения сохраняются автоматически, отдельной кнопки сохранения нет.
- Новый хост появляется в списке, как только введён корректный адрес. [решение]
- Если адрес пустой, а панель закрывают, черновик отбрасывается без вопросов. [решение]

### 3.3 Меню «…» в шапке панели хоста

1. Connect.
2. Add Telnet.
3. Duplicate.
4. Remove.

### 3.4 Панель группы [решение]

- Открывается в правой панели при создании группы (New Group, 2.2) или при редактировании
  (Edit в меню группы). Действует правило сохранения из 1.3; единственное обязательное
  поле — Name.
- Блоки сверху вниз:
  1. **Vault**.
  2. **Name**: обязательное.
  3. **Parent Group**: выбор группы с поиском; пусто — верхний уровень.
  4. **Color**: один из 8 цветов плитки (`docs/design-system.md`, 3.1), по умолчанию
     graphite.
  5. **SSH**: username, identity или ключ, port, Host Chaining.
- Наследование: значения блока SSH действуют на хосты и подгруппы внутри группы. Хост или
  подгруппа без собственного значения берёт значение ближайшей родительской группы, где
  оно задано. В формах хоста и группы унаследованное значение показано плейсхолдером
  «из группы X», где X — группа, из которой оно взято.
- Меню группы (правый клик по карточке группы и меню «…» в шапке панели): Open, Edit,
  Move to, Remove.
- Удаление группы требует подтверждения. Если группа не пустая, диалог сообщает, что её
  подгруппы и хосты переместятся на уровень выше; после этого группа удаляется.

## 4. Сессия терминала

### 4.1 Окно сессии

- Терминал занимает всю область под верхней панелью. Боковой панели Vaults
  и рамок нет, только небольшой внутренний отступ.
- Применяется тема терминала из настроек хоста или тема по умолчанию.
- Пока сессия подключается, во вкладке показан экран подключения (см. 4.8). [решение]
- После подключения выводится только то, что присылает сервер (MOTD и т. п.),
  без собственных баннеров приложения.
- Фокус ввода сразу в терминале.

### 4.2 Боковая панель терминала

- Открывается и скрывается кнопкой в верхней панели (см. 1.1). Панель справа,
  терминал сужается, а не перекрывается.
- Вверху ряд иконок-вкладок: Tools, Snippets, History, Appearance.

**Вкладка Tools:**

- поиск по выводу терминала (Ctrl+Shift+F) с кнопками «предыдущее» и
  «следующее совпадение». Совпадения подсвечиваются в терминале;
- Autocomplete: выпадающий список режимов, по умолчанию выключен.
  Подсказки команд строятся по локальной истории этого хоста. **Поздний этап**,
  в интерфейсе помечен как beta. [решение по источнику подсказок]

**Вкладка Snippets** [решение]:

- список сниппетов с поиском;
- клик вставляет сниппет в терминал без выполнения;
- кнопка «выполнить» вставляет сниппет и сразу отправляет Enter.

**Вкладка History:**

- поиск по истории;
- список введённых команд, новые сверху. Клик вставляет команду в терминал
  без выполнения; [решение]
- карточка-подсказка: три самые частые команды с предложением сохранить их
  как сниппеты. Команды можно отредактировать перед сохранением, есть кнопки
  «Закрыть» и «Сохранить». Закрытая подсказка больше не показывается для этого
  хоста; [решение]
- **Обязательные требования безопасности:**
  - команда — логическая строка в буфере терминала в момент нажатия Enter, без
    приглашения. Приглашение заканчивается на позиции курсора, где был введён первый
    символ команды; [решение]
  - в историю ничего не записывается [решение]:
    - в alternate screen (полноэкранные программы вроде vim или htop);
    - пока сервер не возвращает эхо введённых символов;
    - после строки вывода, похожей на запрос пароля, passphrase, PIN или одноразового
      кода (`password:`, `passphrase`, `PIN`, `OTP`), например от `su`, `sudo`, `passwd`
      или запроса passphrase ключа;
  - такое распознавание команд и приглашений — эвристика с известными ограничениями.
    Разметка приглашения через OSC 133 в MVP не входит; [решение]
  - вырезать управляющие последовательности bracketed paste (`ESC[200~`,
    `ESC[201~`) и прочие escape-коды. В истории хранится только чистый текст
    команды;
  - команды, похожие на секреты, не сохраняются вообще. Команда похожа на секрет, если
    содержит `-p<значение>` (значение сразу после `-p`), `--password`, `*PASSWORD=`,
    `TOKEN=`, `SECRET`, `API_KEY`, `user:pass@`, `Authorization:` или `Bearer`, известный
    префикс токена или высокоэнтропийную строку от 20 символов. Тот же фильтр действует
    при импорте shell history (см. 12.4); [решение]
  - история хранится зашифрованной, как и остальные данные. Синхронизация
    истории между устройствами по умолчанию выключена;
  - запись истории задаётся глобально (см. 12.4) и переопределяется для отдельного хоста
    (Record history, см. 3.1). Любую запись можно удалить, всю историю хоста можно
    очистить; [решение по глобальной настройке]
  - подсказка «сохранить как сниппеты» никогда не предлагает записи, похожие
    на секреты.

**Вкладка Appearance:**

- строка Font со стрелкой ведёт к настройкам шрифта: семейство, размер,
  межстрочный интервал; [решение]
- список Themes: у каждой темы миниатюра-превью в её цветах и название.
  Текущая тема подсвечена. Клик сразу применяет тему к сессии и сохраняет её
  в настройках хоста. Импортированные темы (см. 12.4) в том же списке; [решение]
- счётчиков популярности тем нет, потому что для них нужна телеметрия.
  Темы, добавленные в последнем обновлении, помечены «new»; [решение]
- набор тем: собственные тёмная и светлая по умолчанию плюс популярные
  открытые цветовые схемы с совместимыми лицензиями. Лицензию каждой схемы
  проверить и указать в THIRD_PARTY_NOTICES.

### 4.3 Мышь в терминале

- Правый клик вставляет текст из буфера обмена. Многострочная вставка
  требует подтверждения (см. SPEC.md).
- Если включён copy-on-select, выделение мышью сразу копирует текст. [решение]

### 4.4 Контекстное меню вкладки сессии

1. Duplicate: новая сессия к тому же хосту в новой вкладке.
2. Duplicate in a new window: то же, но в новом окне приложения.
3. Start multiplayer: совместная работа в сессии в реальном времени.
   **Поздний этап.** Работает через self-hosted сервер, с E2E-шифрованием,
   по приглашению. Приглашённый видит вывод и может вводить команды только
   с разрешения владельца сессии. [решение]
4. Rename: переименовать вкладку. Сам хост не переименовывается.
5. Split horizontally: новая панель под текущей (Ctrl+Shift+E, см. 4.7). [решение]
6. Split vertically: новая панель справа от текущей (Ctrl+Shift+D, см. 4.7). [решение]
7. Broadcast input: показан только у вкладки со сплитами (см. 4.7). [решение]
8. Close.

### 4.5 Workspaces

- Workspace: сохранённый набор вкладок и сплитов с привязанными хостами.
  Открытие workspace восстанавливает вкладки и раскладку и подключается
  к хостам.
- Добавить хост: контекстное меню хоста → Add to Workspace ▸ → список
  существующих workspaces и пункт New Workspace (создать и сразу добавить хост).
  [решение по списку существующих]
- Сохранить текущий набор вкладок как workspace можно кнопкой на странице
  новой вкладки (см. раздел 6).
- Workspaces показаны отдельным блоком на странице новой вкладки и находятся
  поиском Ctrl+K. [решение]

### 4.6 Завершение сессии и обрыв соединения

- **Штатное завершение** (`exit`, `logout`, сервер закрыл канал с кодом 0):
  вкладка закрывается сама.
- **Ненулевой код выхода** [решение]: сессия завершилась, а не оборвалась. Вкладка не
  закрывается, вывод сохраняется, поверх терминала сообщение «Сессия завершена с кодом N»
  и кнопки «Переподключиться» и «Закрыть». Автоматическое переподключение не начинается.
- **Неожиданный обрыв**: только ошибка транспорта — сбой сети, таймаут keepalive или
  соединение, закрытое без кода выхода [решение]:
  - вкладка не закрывается, вывод сохраняется;
  - поверх терминала сообщение о причине и кнопки «Переподключиться»
    и «Закрыть»;
  - если Autoreconnect включён (см. 12.4, по умолчанию включён), попытки
    переподключения начинаются автоматически с паузами 1, 2, 4, 8, 16 и 32 секунды,
    а затем каждые 60 секунд. Сообщение показывает обратный отсчёт до следующей попытки
    и кнопку «Отмена», которая останавливает автоматические попытки; [решение]
  - пока приложение заблокировано, переподключение ждёт разблокировки
    (см. 13.3). [решение]
- **Следующая активная вкладка** [решение]: когда активная вкладка сессии закрывается
  по любой причине (штатное завершение, «Закрыть», кнопка закрытия на вкладке,
  Ctrl+Shift+W), активной становится соседняя вкладка сессии: слева, а если её нет, то
  справа. Постоянные вкладки Vaults и SFTP соседними не считаются. Если вкладок сессий
  не осталось, открывается Vaults.
- **Подтверждение выхода** [решение]: Exit (1.4) и закрытие окна, пока есть активные
  сессии, форварды или передачи файлов, сначала запрашивают подтверждение.

### 4.7 Сплиты [решение]

- Вкладку можно разделить на панели по горизонтали (новая панель снизу, Ctrl+Shift+E)
  и по вертикали (новая панель справа, Ctrl+Shift+D): через меню вкладки (4.4) или
  горячими клавишами (настраиваются, см. 12.5). [решение по сочетаниям]
- Новая панель показывает выбор хоста, как на странице новой вкладки (раздел 6): поле
  поиска и Recent connections. Выбор хоста подключает его в этой панели. [решение]
- Границу между панелями можно перетаскивать. Активная панель выделена.
  Фокус переключается кликом или Ctrl+Alt+стрелки (см. 12.5).
- В каждой панели своя сессия, к тому же или к другому хосту.
- **Broadcast input** [решение]: включается и выключается пунктом «Broadcast input»
  в меню вкладки (4.4). Пока он включён, ввод с клавиатуры в активной панели
  отправляется и во все остальные панели вкладки, а эти панели-получатели выделены
  рамкой.

### 4.8 Подключение и аутентификация [решение]

- **Экран подключения.** Пока сессия подключается, во вкладке (или в панели сплита)
  вместо терминала показан экран: имя и адрес хоста, текущий этап (например,
  подключение, проверка ключа хоста, аутентификация, открытие сессии) и кнопка «Отмена».
  Индикатор состояния показывает «подключается» (`docs/design-system.md`, 3.3). «Отмена»
  прерывает попытку, и экран переходит в состояние ошибки, описанное ниже.
- **Ключ хоста.** На этапе проверки ключа хоста при необходимости появляются диалоги
  из 10.2.
- **Запросы.** Когда нужно значение, на экране подключения появляется форма:
  - имя пользователя: когда его не задают ни адрес, ни хост, ни его группа, ни его
    identity (например, быстрое подключение к одиночному `host`, см. 2.1);
  - пароль;
  - passphrase ключа: когда ключ зашифрован и его passphrase не сохранена (см. 7.3);
  - keyboard-interactive: вопросы сервера показываются по одному, над ними имя
    и текст инструкции от сервера. Ответ маскируется, если сервер пометил вопрос как
    вводимый без эха. Так же запрашиваются одноразовые коды (2FA).
- В каждой форме есть кнопки «Продолжить» (Enter) и «Отмена». В формах пароля
  и passphrase есть флажок «Сохранить», по умолчанию выключен. Если он отмечен, значение
  сохраняется в зашифрованном хранилище для этого хоста или ключа. При быстром
  подключении без сохранённого хоста флажок не показывается.
- Когда запрос нужен вне вкладки терминала (панель SFTP, правило форвардинга, запуск
  сниппета с таблицей результатов), та же форма открывается модальным диалогом.
- Неверный пароль или passphrase показывает ошибку в той же форме, и можно попробовать
  снова, пока сервер не закроет соединение.
- **Ошибка.** Если подключиться не удалось (адрес не найден, соединение отклонено или
  истёк таймаут, аутентификация не прошла, ключ хоста отклонён), экран показывает
  причину и кнопки «Повторить» и «Закрыть». Автоматическое переподключение (4.6) к первой
  попытке подключения не применяется.

## 5. SFTP-менеджер (вкладка SFTP)

### 5.1 Раскладка

- Две панели равной ширины. Каждая панель — независимый источник файлов:
  локальный компьютер или удалённый хост.
- По умолчанию слева локальная файловая система, справа пустая панель.
- **Вкладки-сессии SFTP** [решение]: «Connect через SFTP» (2.4) открывает новую вкладку
  сессии с тем же двухпанельным менеджером: слева Local, справа хост. Постоянная вкладка
  SFTP (1.1) остаётся для ручной работы и не меняется.
- Внизу каждой SFTP-вкладки — панель очереди передач (см. 5.6). [решение]

### 5.2 Пустая панель

- По центру: иконка папки, заголовок с призывом подключиться к хосту,
  одна строка пояснения и кнопка выбора хоста.
- Кнопка открывает список сохранённых хостов с поиском. [решение]

### 5.3 Панель с файлами

- Шапка:
  - иконка и название источника (Local или имя хоста). Клик позволяет
    сменить источник; [решение]
  - справа Filter: фильтр по имени в текущей папке;
  - меню Actions (см. 5.5).
- Навигация: кнопки назад и вперёд, путь в виде хлебных крошек. На Windows путь
  начинается с буквы диска, и клик по букве открывает выбор диска. [решение]
  Клик по любому сегменту пути переходит в эту папку.
- Таблица с колонками Name, Date Modified, Size, Kind:
  - сортировка кликом по заголовку колонки, у активной колонки стрелка
    направления сортировки;
  - ширина колонок меняется перетаскиванием. [решение]
- Первая строка «..» переходит на уровень вверх.
- Для папок размер не показывается (прочерк), тип «folder».
- Строка файла:
  - иконка и имя;
  - под именем мелким шрифтом права доступа в формате `-rw-r--r--`
    (только в удалённой панели); [решение]
  - размер в человекочитаемых единицах: байты, КБ, МБ, ГБ;
  - Kind: расширение файла или «file», если расширения нет.
- Выделенная строка подсвечена. Множественное выделение через Ctrl/Shift. [решение]
- Даты отображаются в формате системной локали.
- Двойной клик по папке открывает её. Двойной клик по файлу выполняет
  действие Open (см. 5.4). [решение]
- Перетаскивание файлов между панелями копирует их через очередь передач
  (см. 5.6). Совпадения имён обрабатываются, как описано в 5.7. [решение]

### 5.4 Контекстное меню файла (правый клик)

1. Open: открыть в программе, заданной в «Программа для Open» (см. 12.6), а если она не
   задана — в программе, назначенной в системе для этого типа файла. [решение]
   Удалённый файл скачивается во временную папку, изменения отслеживаются
   и загружаются обратно на сервер, о каждой загрузке приходит уведомление (см. 1.5). [решение]
   Временная копия не зашифрована, поэтому Open показывает предупреждение об этом. Копия
   удаляется при закрытии файла и при выходе из приложения. [решение]
2. Open with…: то же, но с выбором программы.
3. Copy to target directory: скопировать выделенное в текущую папку
   противоположной панели.
4. Rename.
5. Delete: выделено цветом опасного действия, выполняется после подтверждения
   (подтверждение можно выключить, см. 12.6). [решение]
6. Refresh.
7. New Folder.
8. Edit Permissions: диалог прав доступа (см. ниже).

Диалог Edit Permissions [решение]:

- чекбоксы rwx для владельца, группы и остальных;
- синхронизированное поле с восьмеричным значением;
- для папок есть опция «применить рекурсивно».

### 5.5 Меню Actions в шапке панели

Те же пункты, что в контекстном меню (действуют на выделенное), плюс:

- Show Hidden Files: переключатель показа скрытых файлов (по умолчанию выключен,
  см. 12.6); [решение]
- Select All;
- Close: закрыть подключение в этой панели (цвет опасного действия).
  Панель возвращается в пустое состояние из 5.2.

Пункты, которым нужно выделение, без него неактивны. [решение]
В локальной панели на Windows пункт Edit Permissions скрыт. [решение]

### 5.6 Очередь передач [решение]

- Сворачиваемая панель внизу SFTP-вкладки. Появляется, когда добавлена первая передача.
  В свёрнутом виде показывает только заголовок с числом активных передач.
- По строке на передачу: имя файла или папки, направление (загрузка, скачивание или
  с удалённого на удалённый), прогресс, скорость.
- Кнопки строки: «Пауза» и «Продолжить» для активной передачи, «Отмена» и «Повтор» для
  неудавшейся.
- Одновременно выполняется не больше N передач (см. 12.6, по умолчанию 3), остальные ждут
  в очереди.
- Завершённые передачи остаются в списке, пока их не уберут кнопкой «Очистить
  завершённые».

### 5.7 Диалог совпадения имён [решение]

- Показывается, когда у копируемого файла то же имя, что у файла в целевой папке,
  а действие при совпадении имён — «спрашивать» (см. 12.6, по умолчанию).
- Показывает имя файла и для обоих файлов размер и дату изменения.
- Кнопки:
  - Replace: перезаписать файл в целевой папке;
  - Skip: не копировать этот файл;
  - Rename: оставить оба; копируемый файл получает свободное имя с номером, например
    `report (1).txt`.
- Флажок «Применить ко всем» применяет выбор к остальным совпадениям той же операции.

## 7. Экран Keychain

### 7.1 Панель действий

Слева:

- Split-кнопка **New key**. Основная часть открывает в правой панели форму
  добавления существующего ключа: вставить текст, выбрать файл или перетащить
  файл в форму. [решение по drag & drop] Стрелка открывает меню:
  1. **Generate key**: генерация новой пары. Параметры: тип (Ed25519
     по умолчанию, ECDSA, RSA с выбором длины), label, необязательная
     passphrase. [решение по параметрам]
  2. **New Identity**: создать identity.
- **Certificate**: добавить SSH-сертификат.
- **FIDO2**: добавить аппаратный ключ (`sk-ssh-ed25519`, `sk-ecdsa`). [решение по типам]

Справа: поиск, переключатель плитки/список, меню сортировки (по имени,
по дате создания, по дате изменения). Та же иконка сортировки используется
на экране Hosts. [решение]

### 7.2 Содержимое

- Раздел **Keys**, под ним **Identities**. Сетка карточек такая же, как
  на экране Hosts.
- Карточка ключа: иконка, label, подзаголовок «Type» + тип (ED25519, RSA,
  ECDSA, …). Если ключ не удалось разобрать, тип «unknown» и значок
  предупреждения, а причина показана в панели. [решение по предупреждению]
- Карточка identity: иконка, имя, подзаголовок со способом аутентификации
  (пароль, ключ или оба). Если ничего не задано, так и написано: нет способа
  аутентификации.
- Одинаковые ключи (совпадает fingerprint) находятся автоматически. Появляется
  подсказка объединить их в один ключ, ссылки из хостов переносятся. [решение]
- Пустое состояние: кнопки «Сгенерировать», «Импортировать» и
  «Импортировать из ~/.ssh». [решение]

### 7.3 Панель ключа (создание и редактирование)

Блоки сверху вниз:

1. Vault.
2. Label, обязательное поле.
3. Private key, обязательное поле, многострочное, моноширинный шрифт.
4. Public key, многострочное.
5. Certificate, многострочное.
6. Key export: значок «?» с пояснением и кнопка **Export to host**.
   Пользователь выбирает один или несколько хостов, и публичный ключ
   дописывается в `~/.ssh/authorized_keys` без дублей (аналог `ssh-copy-id`).

Меню «…» в шапке: Duplicate, скопировать публичный ключ, экспортировать
в файл, Remove. [решение]

Действует правило сохранения из 1.3: ключ создаётся, когда Label и Private key
корректны. [решение]

**Обязательные требования безопасности:**

- Содержимое приватного ключа по умолчанию **скрыто**. Вместо текста показаны
  тип, fingerprint и пометка, что ключ скрыт.
- Показать ключ можно только явной кнопкой. Когда пользователь уходит
  из панели, ключ снова скрывается.
- Копирование приватного ключа делается отдельной кнопкой. Буфер обмена
  очищается через 30 секунд. [решение по таймауту]
- Если поле Public key пустое, публичный ключ вычисляется из приватного
  автоматически.
- Для каждого ключа показан fingerprint SHA256.
- Ключ без passphrase помечается ненавязчивой подсказкой «не защищён
  passphrase». При экспорте в файл предлагается задать passphrase.
- Passphrase зашифрованного ключа запрашивается при импорте. Пользователь
  выбирает: сохранить её в зашифрованном хранилище или вводить при каждом
  подключении (запрос описан в 4.8).

### 7.4 Панель identity [решение]

- Поля: label, username, password, привязанный ключ или сертификат.
- Внизу список хостов, которые используют эту identity. Клик открывает хост.

## 8. Экран Port Forwarding

### 8.1 Панель действий

- Split-кнопка **New forwarding**: основная часть запускает мастер создания
  (8.3). Стрелка открывает меню: сразу создать Local, Remote или Dynamic
  без мастера. [решение]
- Справа: поиск, переключатель плитки/список, сортировка.

### 8.2 Содержимое

- Раздел со списком правил в виде сетки карточек.
- Карточка правила:
  - квадратный бейдж с буквой типа: L, R или D;
  - label;
  - подзаголовок одной строкой, например `127.0.0.1:8080 → db:5432 через <хост>`; [решение]
  - индикатор состояния: запущено / остановлено / ошибка. [решение]
- Одинарный клик показывает детали в правой панели. Двойной клик запускает
  или останавливает правило. [решение]
- Правый клик [решение]: Start/Stop, Edit, Duplicate, Move to, Copy to, Remove.
  Move to и Copy to в другой vault идут через диалог из 2.6. [решение]

### 8.3 Мастер создания

**Шаг 1: выбор типа**

- Vault.
- Сегментированный переключатель Local / Remote / Dynamic.
- Под ним схема направления трафика для выбранного типа. Схема собственная,
  участники: этот компьютер, межсетевой экран, SSH-хост, целевой сервис или
  интернет. Ниже 1–2 предложения пояснения своими словами:
  - Local: порт, доступный на удалённой стороне, становится доступен на этом
    компьютере, как будто он локальный;
  - Remote: на удалённой машине открывается порт, и подключения к нему
    перенаправляются на этот компьютер;
  - Dynamic: приложение работает как локальный SOCKS-прокси, и все соединения
    через него идут через выбранный SSH-хост.
- Кнопки **Continue** (следующий шаг) и **Skip wizard** (сразу полная форма, 8.4).

**Следующие шаги** [решение]: один вопрос на экран, назад можно вернуться
на любом шаге.

- Local:
  1. через какой хост;
  2. локальный адрес и порт (адрес по умолчанию 127.0.0.1);
  3. адрес и порт назначения (как их видит SSH-хост);
  4. label и итог.
- Remote:
  1. хост;
  2. адрес и порт на удалённой стороне. По умолчанию 127.0.0.1, при выборе
     0.0.0.0 показывается предупреждение и подсказка про `GatewayPorts`;
  3. адрес и порт на этом компьютере;
  4. label и итог.
- Dynamic:
  1. хост;
  2. локальный адрес и порт SOCKS (по умолчанию 127.0.0.1:1080);
  3. label и итог.
- Последний шаг показывает правило одной строкой и кнопки «Создать» и
  «Создать и запустить».

### 8.4 Полная форма (Skip wizard и редактирование) [решение]

- Все поля из мастера на одном экране.
- Дополнительно: запускать правило автоматически при подключении к хосту,
  запускать при старте приложения. Пока приложение заблокировано, автозапуск ждёт
  разблокировки (см. 13.3). [решение]
- Если локальный порт занят, понятная ошибка с номером порта и предложением
  выбрать другой.
- Bind-адрес по умолчанию всегда 127.0.0.1. Открытие порта на все интерфейсы
  (0.0.0.0) требует явного выбора и сопровождается предупреждением.

## 9. Экран Snippets

### 9.1 Панель действий

Слева:

- Split-кнопка **New snippet**. Основная часть создаёт сниппет, стрелка
  открывает меню с пунктом **New snippet package**. Package — папка для
  группировки сниппетов.
- **Shell History**: экран истории команд по всем хостам с поиском, фильтром
  по хосту и действием «сохранить как сниппет». Действуют все правила
  безопасности истории из 4.2. [решение по фильтру]

Справа: поиск, переключатель плитки/список, сортировка.

### 9.2 Содержимое

- Сверху пакеты (как группы на экране Hosts), ниже раздел Snippets. [решение по пакетам]
- Карточка сниппета: иконка, label, а если он пустой, то первая строка скрипта.
  Пока новый сниппет — черновик (см. 1.3), на его карточке плейсхолдер с призывом задать
  label или скрипт. Сниппет создаётся, когда заполнен скрипт. [решение]
- Клики и контекстное меню такие же, как у хостов. Двойной клик запускает
  сниппет на его целевых хостах. [решение]

### 9.3 Панель сниппета (создание и редактирование)

Блоки сверху вниз:

1. Vault.
2. Подсказка про генерацию скрипта по описанию. Показывается один раз,
   закрывается кнопкой «понятно».
3. Основные поля:
   - **Action description**: label сниппета. Справа в поле кнопка
     генерации скрипта по описанию;
   - **Package**: выбор пакета;
   - **Tags**: чипы с автодополнением и созданием новых тегов на лету, как в панели
     хоста (3.1); [решение]
   - **Script**: обязательное, многострочное поле, моноширинный шрифт,
     подсветка shell-синтаксиса. Переменные `{{name}}` подсвечиваются
     и при запуске запрашиваются формой. [решение по подсветке]
4. **Share this snippet**: открывает диалог «Перенести или скопировать в vault» (см. 2.6).
   Неактивна, пока сниппет не сохранён. [решение]
5. **Targets for execution**:
   - короткое пояснение;
   - список целевых хостов (иконка, адрес или label, протокол);
   - ссылка «Add targets» открывает выбор хостов с поиском
     и множественным выбором.
6. Кнопка **Run** закреплена внизу. Неактивна, пока нет скрипта и хотя бы
   одной цели.

### 9.4 Запуск на нескольких хостах [решение]

- До 4 целей: новая вкладка, разделённая на панели, по одной сессии на хост.
  Скрипт выполняется в каждой.
- Больше 4 целей: вкладка с таблицей результатов. Для каждого хоста видны
  статус (ожидает, выполняется, успех, ошибка), код выхода и вывод,
  который раскрывается по клику.
- Перед запуском на 2+ хостах показывается подтверждение со списком хостов.

### 9.5 Генерация скрипта по описанию [решение, поздний этап]

- По умолчанию выключена. Включается в настройках с указанием провайдера:
  собственный API-ключ к LLM или локальная модель.
- Описание отправляется провайдеру только по явному нажатию кнопки
  генерации. Пользователю явно показано, куда уйдёт текст.
- Сгенерированный скрипт только вставляется в поле Script. Автоматически
  он никогда не выполняется.

## 10. Экран Known Hosts

### 10.1 Список

- Панель действий: кнопка **Import** открывает диалог импорта (2.5) с источником
  known_hosts; по умолчанию предлагается `~/.ssh/known_hosts`. Справа поиск,
  переключатель вида, сортировка. [решение]
- Сетка карточек: иконка отпечатка и адрес в формате OpenSSH. Для порта 22
  это `host`, для остальных `[host]:port`.
- Хэшированные записи (`|1|…`) хранятся как есть, потому что их адрес восстановить
  нельзя. На их карточке вместо адреса «Хэшированная запись» и тип ключа. При
  подключении адрес хэшируется (HMAC) и сравнивается с этими записями. [решение]
- Записи `@revoked` импортируются как отозванные ключи и помечаются бейджем «отозван».
  Записи `@cert-authority` пропускаются, итог импорта показывает, сколько их
  пропущено. [решение]
- Клик открывает правую панель [решение]: адрес, порт, тип ключа, fingerprint
  SHA256 с кнопкой копирования, дата добавления, сохранённые хосты с этим
  адресом, кнопка Remove.
- Правый клик [решение]: скопировать fingerprint, Remove.
- Экспорт в формат known_hosts. Хэшированные записи экспортируются как есть. [решение]
- При подключении ключи хостов проверяются только по этому списку. Системный
  `~/.ssh/known_hosts` при подключении не читается, его можно только
  импортировать. [решение]

### 10.2 Первое подключение и смена ключа [решение]

- Первое подключение (TOFU) открывает диалог: адрес, тип ключа, fingerprint.
  Кнопки: «Принять и сохранить» (по умолчанию), «Подключиться один раз»,
  «Отмена».
- Если ключ хоста изменился:
  - подключение блокируется, показано предупреждение цветом опасности;
  - видны старый и новый fingerprint и пояснение о возможной атаке;
  - продолжить можно только явной кнопкой «Заменить сохранённый ключ»;
  - флажков вроде «больше не спрашивать» нет.
- Если ключ хоста есть в списке как отозванный (10.1), подключение блокируется
  с предупреждением цветом опасности. Кнопки продолжить нет. [решение]

## 11. Экран Logs

Журнал подключений в виде таблицы.

### 11.1 Колонки

- **Date** с переключателем порядка сортировки:
  - дата начала сессии;
  - ниже время начала и конца. Если сессия закончилась на следующий день,
    добавляется «(+1d)»;
  - у активной сессии вместо времени конца «сейчас». [решение]
- **User**: аватар и аккаунт, ниже имя устройства. IP-адрес клиента не собирается
  и не показывается. [решение]
  - В командном vault журнал показывает только записи участников, которые включили
    публикацию для этого vault (см. 12.3). [решение]
  - Пока командные vault не реализованы (этап 8), колонка показывает текущее
    устройство. [решение]
- **Host**: иконка ОС, имя хоста, ниже протокол и пользователь.
- **Saved**: кнопка-закладка. Сохранённые записи не удаляются автоочисткой.
  Клик по заголовку колонки показывает только сохранённые. [решение]

### 11.2 Действия [решение]

- Клик по строке: если вывод сессии записывался (глобальная настройка в 12.6 или
  переопределение Record output у хоста в 3.1), открывается запись только для чтения,
  с поиском и экспортом в .txt. Если не записывался, показываются детали подключения.
- Экспорт в .txt записывает незашифрованный текст, поэтому сначала показывается
  предупреждение.
- Записи вывода хранятся зашифрованными и никогда не синхронизируются.
- Журнал всегда пишется в личный vault и хранится зашифрованным. Синхронизация журнала
  между устройствами включается отдельно (см. 12.2).

### 12.2 Account & Sync

Приложение работает без аккаунта. Без подключённого сервера здесь только
кнопка «Подключить сервер синхронизации» (открывает мастер, см. 13.5) и экспорт
данных. [решение]

С подключённым сервером:

- адрес сервера; email аккаунта с отметкой «подтверждён / не подтверждён»;
  смена email. Отметка скрыта, если на сервере не настроена почта (SMTP); [решение]
- двухфакторная аутентификация (TOTP) на сервере: переключатель;
- **Log out**: выход с этого устройства. Пользователь выбирает, оставить
  локальную копию или удалить её с устройства. По умолчанию копия остаётся
  (принцип 3 в SPEC.md);
- смена мастер-пароля и recovery key находятся в Settings → Security (см. 13.4),
  потому что они есть и без сервера; [решение]
- удаление аккаунта на сервере. Локальная копия при этом остаётся.
  Если аккаунт — единственный owner командного vault, удаление заблокировано, пока
  владение не передано другому участнику (см. 12.3). [решение]

Блок **Synchronization**:

- переключатели задаются для этого устройства и действуют и на отправку, и на получение
  изменений. Выключение переключателя останавливает синхронизацию этого типа, но не
  удаляет данные с сервера; [решение]
- переключатели действуют на личный vault. Командные vault всегда синхронизируются
  целиком; [решение]
- переключатели, что синхронизировать:
  - хосты и группы (по умолчанию вкл);
  - ключи и identities (по умолчанию вкл);
  - сниппеты (по умолчанию вкл);
  - правила форвардинга (по умолчанию вкл);
  - known hosts (по умолчанию вкл); [решение]
  - workspaces (по умолчанию вкл); [решение]
  - пользовательские темы терминала (по умолчанию вкл); [решение]
  - правила подсветки ключевых слов (по умолчанию вкл); [решение]
  - история команд (по умолчанию **выкл**);
  - журнал подключений (по умолчанию **выкл**);
- настройки приложения не синхронизируются, они остаются на каждом устройстве. Записи
  вывода сессий не синхронизируются никогда (см. 11.2); [решение]
- время последней синхронизации и ошибки, если они есть;
- строка «Конфликты: N», показана, пока есть неразрешённые конфликты. Клик открывает
  список конфликтов (см. 13.6); [решение]
- кнопка «Синхронизировать сейчас».

Также:

- кнопка экспорта всех данных (JSON открытый или зашифрованный, ssh config).
  Доступна всегда. Открытый JSON содержит секреты в незашифрованном виде, поэтому
  сначала показывается предупреждение; [решение]
- никаких триалов, тарифов и кнопок покупки.

### 12.3 SSH ID и Team [решение]

- **SSH ID**: личный Ed25519-ключ пользователя, хранится в личном Keychain. На сервер
  публикуется только его публичная часть. Когда у хоста в командном vault нет
  credentials, каждый участник подключается своим SSH ID или identity (см. 2.6), так что
  общий пароль или ключ не нужен. Здесь можно показать и скопировать публичный ключ
  и выгрузить его на хосты.
- **Team**:
  - участники vault с ролями owner / editor / viewer. У vault может быть несколько owner;
  - рядом с каждым участником отпечаток его ключа для сверки вне сервера (например,
    лично или по телефону). Ключ закрепляется при первом использовании;
  - приглашение в два шага:
    1. owner создаёт ссылку-приглашение. Ссылка содержит только одноразовый ID и никогда
       не содержит ключей. Если на сервере настроена почта (SMTP), приглашение можно
       отправить и по email, иначе доступна только ссылка;
    2. после того как приглашённый принял приглашение, owner сверяет отпечаток его ключа
       и подтверждает. Только после этого приглашённый получает доступ к vault;
  - диалог приглашения прямо говорит, что каждый участник, включая viewer, получает все
    секреты vault (пароли и ключи его хостов);
  - удаление участника создаёт новый ключ vault, и приложение owner'а в фоне
    перешифровывает записи vault (см. SPEC.md). Диалог предлагает сменить пароли и ключи
    хостов vault, потому что удалённый участник их видел;
  - у удалённого участника vault остаётся локальным архивом только для чтения
    с действиями «Экспорт» и «Скопировать в личный vault» (принцип 3 в SPEC.md);
  - «Публиковать мой журнал подключений»: переключатель для каждого командного vault,
    по умолчанию выключен. Когда он включён, твои записи журнала по хостам этого vault
    видны его участникам (см. 11.1). Публиковать может и viewer.

### 12.4 Terminal

**Блок «Терминал»:**

- Autocomplete (beta): выпадающий список, по умолчанию выключен. Поздний этап.
- Autoreconnect: переключатель, по умолчанию включён (см. 4.6).
- Record command history: переключатель, по умолчанию включён. Хост может его
  переопределить (см. 3.1). [решение]
- Import shell history: подтягивать историю из `~/.bash_history` и
  `~/.zsh_history` сервера в панель History. По умолчанию **выключено**,
  потому что такие файлы часто содержат секреты. При импорте действуют те же
  фильтры, что в 4.2, и команды, похожие на секреты, пропускаются. [решение]
- Copy on select: переключатель. Правый клик вставляет текст всегда (см. 4.3). [решение]
- Bell sound: по умолчанию выключен.
- Bright colors for bold text: переключатель.
- Cursor style: block / bar / underline, по умолчанию block; Blinking: переключатель,
  по умолчанию выключен. [решение]
- Terminal emulation type: значение TERM, по умолчанию `xterm-256color`.
  Варианты: `xterm`, `xterm-256color`, `vt100`, `linux`.

**Блок шрифта:**

- выбор шрифта: поиск по установленным моноширинным шрифтам и встроенным
  открытым шрифтам;
- размер текста: кнопки −/+ и поле с числом, по умолчанию 14.

**Блок «Тема терминала»:**

- тема по умолчанию для новых хостов. Выбор такой же, как в 4.2;
- «Import theme…»: импорт файлов `.itermcolors` и цветовых схем Windows Terminal. Они
  конвертируются в собственный формат тем приложения (`docs/design-system.md`, §7)
  и появляются в списках тем (4.2). Импортированные темы хранятся записями
  и синхронизируются (см. 12.2). [решение]

**Блок «Подсветка ключевых слов»:**

- общий переключатель, по умолчанию включён;
- категории с выбором цвета: Error, Warning, OK, Info, Debug, IP- и MAC-адреса.
  У каждой категории есть цвет по умолчанию для тёмного и для светлого фона; какой из
  них используется, зависит от яркости фона темы терминала, а не от темы интерфейса.
  Цвета хранятся в hex; [решение]
- собственные правила: regex + цвет + вкл/выкл; [решение]
- подсветка меняет только отображение, не данные. В полноэкранных программах
  (alternate screen: vim, htop) отключается. [решение]

**Блок «Определение ОС»:**

- пояснение: при первом подключении к хосту выполняется короткий скрипт,
  который определяет ОС для иконки. Скрипт запускается, только если сервер
  сам не сообщил ОС;
- переключатель, по умолчанию включён;
- «Скрипт определения ОС»: просмотр и редактирование скрипта, кнопка
  «Сбросить к стандартному»;
- скрипт выполняется в отдельном exec-канале, не в интерактивной сессии,
  и не попадает в историю. [решение]

**Блок «Оболочка локального терминала»:** выпадающий список найденных
оболочек плюс свой путь.

- Windows: PowerShell, PowerShell 7, cmd, дистрибутивы WSL, Git Bash.
- macOS и Linux: оболочки из `/etc/shells`.

**Блок «Keepalive»:**

- пояснение: как часто (в секундах) отправлять SSH keepalive, 0 означает
  «выключено»;
- поле Interval, по умолчанию 30, чтобы обрывы обнаруживались вовремя. [решение]
- Хост может переопределить интервал (см. 3.1). [решение]

### 12.5 Shortcuts

- Сверху выбор набора клавиш: PC или Mac. По умолчанию Mac на macOS и PC на Windows
  и Linux. [решение по наборам]
- Таблица Shortcut | Action:
  - клик по сочетанию включает запись нового сочетания;
  - конфликты подсвечиваются;
  - любое действие можно сделать «не назначено».

Набор по умолчанию для Windows/Linux:

| Сочетание | Действие |
|---|---|
| Ctrl+1…9 | перейти на вкладку N (1 = Vaults, 2 = SFTP) |
| Ctrl+Alt+стрелки | фокус между панелями сплита |
| Ctrl+Shift+D | разделить по вертикали: новая панель справа [решение] |
| Ctrl+Shift+E | разделить по горизонтали: новая панель снизу [решение] |
| Ctrl+Shift+C | копировать из терминала |
| Ctrl+Shift+V | вставить в терминал |
| Ctrl+Shift+A | выделить всё в терминале |
| не назначено | открыть экран Hosts |
| Ctrl+L, Ctrl+Shift+L | новый локальный терминал [решение по Ctrl+Shift+L] |
| Ctrl+Alt+S | новое serial-подключение |
| Ctrl+Shift+W | закрыть вкладку |
| Alt+→ | следующая вкладка |
| Alt+← | предыдущая вкладка |
| Ctrl+P, Ctrl+Shift+P | открыть Port Forwarding [решение по Ctrl+Shift+P] |
| Ctrl+K, Ctrl+Shift+K | поиск по хостам и вкладкам [решение] |
| Ctrl+Shift+F | поиск в терминале |
| Ctrl+, | настройки |

**Важно** [решение]: сочетания без Shift (Ctrl+L, Ctrl+P, Ctrl+K) совпадают
с клавишами shell: `Ctrl+L` очищает экран, `Ctrl+P` вызывает предыдущую
команду, `Ctrl+K` удаляет до конца строки. Когда фокус в терминале, такие
сочетания уходят в shell, а не в приложение. Действия приложения из терминала
доступны через сочетания с Ctrl+Shift: Ctrl+Shift+L, Ctrl+Shift+P и Ctrl+Shift+K
работают везде.

**Фокус в терминале** [решение]:

- Когда фокус в терминале, приложение перехватывает только: Ctrl+1…9, `Ctrl+,`, все
  сочетания с Ctrl+Shift, Ctrl+Alt+стрелки, Alt+← и Alt+→. Все остальные сочетания
  уходят в shell, например Ctrl+L или Ctrl+Alt+S.
- Alt+← и Alt+→ в readline переходят по словам; пока они назначены на вкладки, shell их
  не получает. Их можно переназначить в этой таблице.
- Пока активен AltGr, сочетания не срабатывают. На Windows во многих раскладках Ctrl+Alt
  равносилен AltGr, поэтому клавиша вводит свой символ.

**Набор Mac** [решение]:

- Действия приложения вызываются через Cmd вместо Ctrl (например, Cmd+1…9, `Cmd+,`,
  Cmd+K).
- Ctrl+буква всегда уходит в shell.
- Option вводит символы и для сочетаний приложения не используется.
- Полная таблица Mac добавляется в этот раздел до этапа 6.

### 12.6 SFTP и Logs [решение]

- **SFTP:**
  - показывать скрытые файлы: по умолчанию выключено;
  - подтверждение удаления: по умолчанию включено;
  - действие при совпадении имён: спрашивать (по умолчанию, см. 5.7), заменять,
    пропускать или переименовывать;
  - число параллельных передач: по умолчанию 3 (см. 5.6);
  - программа для Open: по умолчанию пусто, то есть программа, назначенная в системе
    для типа файла (см. 5.4). «Open with…» всегда спрашивает программу.
- **Logs:**
  - срок хранения журнала подключений: по умолчанию 90 дней. Сохранённые записи
    остаются (см. 11.1);
  - запись вывода сессий: глобальный переключатель, по умолчанию выключен,
    с предупреждением, что в выводе бывают секреты. Хост может его переопределить
    (см. 3.1). Записи хранятся зашифрованными и никогда не синхронизируются;
  - очистка журнала.

### 12.7 Updates [решение]

- Автоматическая проверка обновлений: переключатель, по умолчанию выключен. Когда он
  включён, приложение проверяет источник обновлений при запуске.
- Пояснение под переключателем говорит, что проверка — это простой запрос манифеста
  обновлений без каких-либо идентификаторов.
- Источник обновлений: поле URL, по умолчанию релизы репозитория проекта, и кнопка
  «Сбросить к стандартному».
- Кнопка «Проверить сейчас»: то же действие, что Help ▸ «Проверить обновления» (1.4).
- Когда обновление найдено, в верхней панели появляется кнопка обновления (1.1).
  Обновление, подпись которого не совпадает с ключом подписи проекта, не
  устанавливается.

## 13. Блокировка и аккаунт [решение]

Мастер-пароль обязателен с первого запуска, даже без аккаунта и сервера. Тот же пароль
потом становится паролем аккаунта синхронизации. Иерархия ключей описана
в `docs/security.md`.

### 13.1 Первый запуск

- При первом запуске, до любого другого экрана, приложение просит создать мастер-пароль:
  - поля «Пароль» и «Повтор пароля», маскированы, с кнопками показать/скрыть;
  - «Продолжить» активна, когда оба поля заполнены и совпадают.
- На экране всегда показано предупреждение, а не закрываемая подсказка: без
  мастер-пароля и recovery key данные не сможет восстановить никто, включая
  администратора сервера.
- Следующий шаг — recovery key:
  - ключ показан текстом моноширинным шрифтом, с кнопкой «Копировать». Буфер обмена
    очищается через 30 секунд, как для приватных ключей (см. 7.3);
  - флажок «Я сохранил recovery key» обязателен: «Готово» неактивна, пока он не
    отмечен.
- После «Готово» открывается вкладка Vaults с пустым экраном Hosts (см. 2.3).

### 13.2 Экран разблокировки

- Показывается при каждом запуске и после блокировки (см. 13.3). Закрывает всё
  содержимое окна, включая вкладки и открытые диалоги; доступны только кнопки окна.
- Содержимое: название приложения, поле «Мастер-пароль» с фокусом в нём, кнопка
  «Разблокировать» (Enter) и ссылка «Использовать recovery key».
- Неверный пароль показывает ошибку под полем; поле очищается, фокус остаётся в нём.
- Если включено «Запомнить на этом устройстве» (см. 13.4), приложение при запуске
  разблокируется без запроса пароля. Ручная блокировка и автоблокировка всё равно
  требуют пароль.
- **Использовать recovery key**: пользователь вводит recovery key, затем новый
  мастер-пароль и его повтор, и приложение разблокируется. С сервером синхронизации
  восстановление обычно идёт через сервер: новый пароль становится и паролем аккаунта, а
  другие устройства выходят из аккаунта, как после смены пароля (см. 13.4).
  - С сервером синхронизации диалог показывает и email аккаунта, заполненный заранее и
    доступный для правки. Если сервер не принимает ключ, диалог сообщает, что email мог
    измениться на другом устройстве, а не только что ключ может быть неверным.
  - Если сервер недоступен или не принимает восстановление, диалог предлагает восстановить
    только данные на этом устройстве: новый пароль открывает локальную копию, а это
    устройство выходит из аккаунта, пока пользователь не войдёт с паролем аккаунта или не
    восстановит доступ через сервер.

### 13.3 Блокировка и автоблокировка

- Приложение блокируется:
  - пунктом Lock в меню приложения (см. 1.4);
  - автоматически, если пользователь ничего не вводил дольше интервала автоблокировки
    (см. 13.4). Считается только ввод с клавиатуры и мыши в окнах приложения, вывод
    терминала не считается.
- Блокировка действует сразу на все окна.
- При блокировке:
  - экран разблокировки (13.2) закрывает каждое окно: вывод терминала, панели и диалоги
    скрыты;
  - установленные сессии, форварды и уже идущие передачи файлов продолжают работать;
  - ключи vault и расшифрованные секреты стираются из памяти;
  - всё, чему нужны секреты, ждёт разблокировки: автоматическое переподключение
    (см. 4.6) и автозапуск правил форвардинга (см. 8.4).
- После разблокировки каждое окно возвращается в состояние, которое было до блокировки.

### 13.4 Настройки безопасности

Settings → Security (см. 12.1):

- **Автоблокировка**: выпадающий список интервалов (1, 5, 15, 30 или 60 минут), по
  умолчанию 15 минут. Вариант «Никогда» выключает автоблокировку.
- **Смена мастер-пароля**: текущий пароль, новый пароль и его повтор.
  - Работает и без сервера. Смена вступает в силу сразу.
  - С сервером синхронизации для смены нужно соединение с сервером. Перед подтверждением
    предупреждение говорит, что другие устройства выйдут из аккаунта и запросят новый
    пароль.
- **Recovery key**: «Показать» и «Перевыпустить», оба после ввода мастер-пароля.
  «Перевыпустить» создаёт новый ключ и показывает его, как в 13.1, с обязательным
  флажком «Я сохранил»; старый ключ перестаёт работать.
- **Запомнить на этом устройстве**: переключатель, по умолчанию выключен. Когда он
  включён, ключ устройства хранится в OS keychain, и приложение при запуске
  разблокируется без пароля (см. 13.2).
  - При включении показывается предупреждение: любая программа, запущенная под этим
    пользователем ОС, сможет разблокировать данные.
  - Скрыт, если в ОС нет keychain (например, Linux без Secret Service), и в неподписанных
    сборках для macOS.
  - Разблокировка биометрией — поздний этап, до него скрыта.

### 13.5 Мастер подключения сервера синхронизации

- Открывается кнопкой «Подключить сервер синхронизации» (см. 12.2). Модальный диалог по
  шагам, на каждом шаге есть кнопка «Назад»:
  1. **Сервер**: URL сервера. Приложение проверяет, что сервер отвечает, и показывает
     ошибку, если нет.
  2. **Вход или регистрация**:
     - вход: email и мастер-пароль аккаунта;
     - регистрация: email и текущий мастер-пароль, введённый ещё раз для подтверждения.
       Если сервер разрешает регистрацию только по приглашению, показано поле «Инвайт-код»,
       и оно обязательно.
  3. **TOTP**:
     - вход: одноразовый код, если для аккаунта включён TOTP;
     - регистрация: предложение включить TOTP сейчас (QR-код, секрет текстом и код для
       подтверждения). Шаг можно пропустить и включить TOTP позже (см. 12.2).
  4. **Recovery key** (только при регистрации): recovery key, который теперь защищает
     и аккаунт, показан с обязательным флажком «Я сохранил», как в 13.1. Если данные на
     этом устройстве раньше были подключены к другому аккаунту, регистрация создаёт новый
     recovery key, и этот шаг показывает новый.
- Мастер-пароль никогда не покидает устройство; сервер получает только выведенный из
  него ключ.
- Вход в существующий аккаунт на устройстве, где уже есть локальные данные, сливает
  данные: локальные записи перешифровываются ключами аккаунта и сливаются с данными
  аккаунта с дедупликацией, как при импорте (см. 2.5). После этого устройство использует
  мастер-пароль аккаунта. Мастер сообщает об этом до слияния.
- Когда мастер завершён, начинается синхронизация, а Account & Sync (12.2) показывает
  подключённый сервер.

### 13.6 Конфликты синхронизации

- Когда синхронизация сохраняет проигравшую версию объекта, карточка объекта показывает
  бейдж конфликта во всех списках (хосты, группы, ключи, identities, правила форвардинга,
  сниппеты, known hosts), а Account & Sync (12.2) показывает «Конфликты: N».
- Клик по бейджу или по конфликту в списке, открытом из «Конфликты: N», открывает диалог
  сравнения:
  - две версии рядом: слева текущая версия, справа другая. У каждой указаны устройство
    и время изменения, отличающиеся поля подсвечены;
  - пароли остаются маскированными, приватные ключи скрытыми (см. 7.3);
  - если одна из версий — удаление, на её стороне написано «Удалено»;
  - кнопка «Оставить эту» оставляет текущую версию, кнопка «Оставить другую» заменяет её
    другой версией.
- Закрытие диалога без выбора оставляет конфликт неразрешённым. После выбора другая
  версия удаляется, и бейдж пропадает на всех устройствах после следующей синхронизации.
